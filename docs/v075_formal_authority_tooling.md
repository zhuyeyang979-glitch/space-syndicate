# V0.7.5 Global Matrix Authority and Local UID Attestation

This tooling prepares identity evidence only. It never launches Godot, MCP, a
simulation worker, or a formal shard.

Formal identity has two deliberately separate layers:

1. **Global matrix authority** is deterministic semantic authority shared by
   every worker and worktree. Its file SHA-256 is stable for the same HEAD,
   tree, harness, ruleset, step limit, five-configuration matrix, seed formula,
   and canonical job plan.
2. **Local UID attestation** is execution evidence for one absolute worktree.
   It may contain paths and capture times. It binds that worktree's pre-import
   baseline and closed generated-UID allowlist to the global authority, but it
   is never part of a match job identity.

The field retained by the planner and simulator has one exact meaning:

```text
authority_manifest_sha256 = SHA256(global-matrix-authority.json file bytes)
authority_manifest_scope = global_matrix
```

It never means a local baseline, UID allowlist, local UID attestation, worker
manifest, shard receipt, or a hash derived from any absolute worktree path.
The simulator launch option named `harness_hash` is populated from the global
authority's `harness_fingerprint`; the exact job-identity field remains
`harness_fingerprint`.

## Deterministic global matrix authority

Create this once after final HEAD/tree and the harness fingerprint are frozen.
The schema is `space_syndicate.v075.global_matrix_authority.v1`. Its exact
top-level fields are:

```text
schema
authority_scope
authority_manifest_semantics
final_head_sha
final_tree_sha
harness_fingerprint
simulation_id
ruleset_id
configuration_ids
configuration_count
matches_per_configuration
total_match_count
step_limit
base_seed
seed_configuration_stride
seed_match_stride
minimum_matches_per_shard
maximum_matches_per_shard
canonical_job_descriptor_fields
canonical_job_count
canonical_job_plan_sha256
configuration_plan
job_identity_binding_fields
job_identity_excluded_execution_fields
```

`configuration_ids` is the fixed ordered matrix:

```text
3p_8r_simple
4p_16r_standard
4p_24r_complex
6p_24r_standard
8p_30r_complex
```

Each `configuration_plan` entry binds its index/ID, zero-based match range,
match count, seed base, seed stride, and step limit. The canonical job-plan hash
covers every `configuration_index|configuration_id|match_index|seed|step_limit`
row in deterministic order. The global file contains no timestamps, absolute
paths, baseline/allowlist fields, UID fields, worker identity, process identity,
or local attestation hash. Exact canonical regeneration and an externally frozen
expected file SHA-256 are both required.

```powershell
pwsh -NoProfile -File tools/invoke_v075_formal_authority.ps1 `
  -Operation create-global-matrix-authority `
  -ExpectedHeadSha <40-lowercase-hex-head> `
  -ExpectedTreeSha <40-lowercase-hex-tree> `
  -HarnessFingerprint <64-lowercase-hex-harness-hash> `
  -MatchesPerConfiguration 50 `
  -StepLimit 512 `
  -OutputPath E:\evidence\global-matrix-authority.json
```

Freeze the returned `output_sha256` in an approved launch-control record or
immutable sidecar. A manifest cannot attest its own hash. Re-running the command
with identical semantic inputs produces identical file bytes and SHA-256 even
when the output path is different.

## Per-worktree controlled import and UID evidence

For every isolated worktree:

1. Check out the frozen final HEAD/tree.
2. Capture `capture-preimport-baseline`. It fails unless the worktree has zero
   tracked modifications and zero untracked files.
3. Run the separately authorized controlled Godot import and preserve its raw
   process, diagnostic, and clean-stop evidence. Before accepting the import,
   require its tracked `.import` drift to equal the complete canonical 57-path
   set and canonical generated byte map frozen in
   `tools/invoke_v075_mcp_validation_runbook.ps1`; record the raw diff, then
   restore exactly those 57 paths to HEAD. Any subset, extra path, or different
   bytes fails closed and is not cleaned automatically.
4. With the generated UIDs still present and tracked state restored to HEAD,
   capture `capture-uid-allowlist`. It accepts only newly generated `.gd.uid`
   and `.gdshader.uid` files whose sources are tracked and still exist. It binds
   each UID relative path, source relative path, UID value, byte length, and
   content SHA-256. Any tracked modification or non-UID untracked file fails.
5. Create a local UID attestation that binds the two local evidence file hashes
   to the externally frozen global matrix authority SHA-256.
6. Freeze the local attestation's returned `output_sha256` externally.
7. Run `verify-worktree` immediately before and after every shard assigned to
   that worktree.

For exact-SHA MCP validation, perform this controlled preimport in a separate
sibling worktree and stop it before starting the MCP role. Freeze the returned
allowlist file SHA outside every worktree, clean the MCP worktree completely,
then pass the external allowlist path and independently frozen SHA to
`tools/invoke_v075_mcp_validation_runbook.ps1`. The MCP runbook consumes the
same v1 rows as an execution/cleanup authority; it does not derive authority
from post-run filename suffixes. This MCP use does not change the formal shard
validator: formal `verify-worktree` continues to require exact set equality.

```powershell
pwsh -NoProfile -File tools/invoke_v075_formal_authority.ps1 `
  -Operation capture-preimport-baseline `
  -Worktree E:\path\to\formal-worktree `
  -ExpectedHeadSha <40-lowercase-hex-head> `
  -ExpectedTreeSha <40-lowercase-hex-tree> `
  -OutputPath E:\evidence\worker-0\preimport-baseline.json

pwsh -NoProfile -File tools/invoke_v075_formal_authority.ps1 `
  -Operation capture-uid-allowlist `
  -Worktree E:\path\to\formal-worktree `
  -PreimportBaselinePath E:\evidence\worker-0\preimport-baseline.json `
  -OutputPath E:\evidence\worker-0\generated-uid-allowlist.json

pwsh -NoProfile -File tools/invoke_v075_formal_authority.ps1 `
  -Operation create-local-uid-attestation `
  -Worktree E:\path\to\formal-worktree `
  -PreimportBaselinePath E:\evidence\worker-0\preimport-baseline.json `
  -UidAllowlistPath E:\evidence\worker-0\generated-uid-allowlist.json `
  -GlobalMatrixAuthorityPath E:\evidence\global-matrix-authority.json `
  -ExpectedGlobalMatrixAuthoritySha256 <64-hex-global-file-hash> `
  -OutputPath E:\evidence\worker-0\local-uid-attestation.json
```

The local schema is `space_syndicate.v075.local_uid_attestation.v1`. Its exact
fields are:

```text
schema
attestation_scope
attested_at_utc
worktree
final_head_sha
final_tree_sha
global_matrix_authority_path
global_matrix_authority_sha256
preimport_baseline_path
preimport_baseline_sha256
generated_uid_allowlist_path
generated_uid_allowlist_sha256
uid_entry_set_sha256
uid_entry_count
tracked_modification_count_at_attestation
untracked_count_at_attestation
generated_uid_allowlist_match
purpose
excluded_from_job_identity
```

Different worktrees and capture times normally produce different baseline,
allowlist, and local-attestation hashes. That is expected execution evidence,
not semantic job drift. Every local attestation must bind the same externally
frozen global authority SHA for one matrix run.

## Before/after shard verification

```powershell
pwsh -NoProfile -File tools/invoke_v075_formal_authority.ps1 `
  -Operation verify-worktree `
  -Worktree E:\path\to\formal-worktree `
  -PreimportBaselinePath E:\evidence\worker-0\preimport-baseline.json `
  -UidAllowlistPath E:\evidence\worker-0\generated-uid-allowlist.json `
  -GlobalMatrixAuthorityPath E:\evidence\global-matrix-authority.json `
  -ExpectedGlobalMatrixAuthoritySha256 <64-hex-global-file-hash> `
  -LocalUidAttestationPath E:\evidence\worker-0\local-uid-attestation.json `
  -ExpectedLocalUidAttestationSha256 <64-hex-local-file-hash>
```

Verification requires all of these simultaneously:

```text
TRACKED_MODIFICATION_COUNT=0
UNTRACKED_NON_ALLOWLIST_COUNT=0
GENERATED_UID_ALLOWLIST_MATCH=true
GLOBAL_MATRIX_AUTHORITY_HASH_MATCH=true
GLOBAL_MATRIX_AUTHORITY_DETERMINISTIC_CONTRACT_MATCH=true
GLOBAL_AUTHORITY_HEAD_TREE_MATCH=true
LOCAL_UID_ATTESTATION_HASH_MATCH=true
LOCAL_UID_ATTESTATION_CONTRACT_MATCH=true
LOCAL_BASELINE_HASH_MATCH=true
LOCAL_ALLOWLIST_HASH_MATCH=true
LOCAL_UID_ATTESTATION_EXCLUDED_FROM_JOB_IDENTITY=true
```

Missing, additional, modified, malformed, duplicate, or source-less UID files
fail closed. So do baseline-clean flag drift, capture-count drift, evidence-file
replacement, global or local expected-SHA drift, a global file containing local
fields, or disagreement among global HEAD/tree, local evidence, and the actual
worktree. No `.gitignore` broadening and no `git clean` operation belongs to
this flow.

## Shard plan and exact job identity

The planner consumes the validated global file; it no longer accepts an
independent HEAD, tree, harness, match count, or step limit that could disagree
with that authority.

```powershell
pwsh -NoProfile -File tools/invoke_v075_formal_authority.ps1 `
  -Operation plan-shards `
  -GlobalMatrixAuthorityPath E:\evidence\global-matrix-authority.json `
  -ExpectedGlobalMatrixAuthoritySha256 <64-hex-global-file-hash> `
  -WorkerCount 5 `
  -OutputPath E:\evidence\formal-shard-plan.json
```

The planner partitions each configuration into contiguous 10-20 match shards:

- 20 matches/configuration: five 20-match shards.
- 50 matches/configuration: per configuration `17 + 17 + 16`, fifteen shards.
- 400 matches/configuration: twenty 20-match shards per configuration, one
  hundred shards total.

Every exact job identity binds final HEAD, final tree, the global authority file
SHA in `authority_manifest_sha256`, harness fingerprint, simulation/ruleset,
configuration index and ID, match index, deterministic seed, and step limit. It
excludes worker, session, process, shard, absolute worktree, and local UID
attestation identity. A failed job may therefore move to a newly attested
worktree without changing its exact identity.

The planner only creates evidence; it does not authorize or dispatch a shard.
A separate user decision is still required before any formal simulation launch.
